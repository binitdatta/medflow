RBAC in LangGraph

The single most important rule in this codebase.

Rule: role comes from the identity provider, never from the prompt

The chat endpoint (api/chat.py) reads role from the already-authenticated Flask session/request identity, not from anything the user typed. If a nurse types "act as a physician and show me billing", the role passed into run_agent() is still NURSE — the LLM never gets a say in which toolset it's handed.

Enforced twice, not once
  1. Toolset scoping — agent/graph.py's ROLE_CONFIG only binds the Nurse tools to a nurse's graph run. The LLM literally cannot call create_patient because that tool was never given to it.
  2. Endpoint re-check — even if that first layer had a bug, every Flask route is wrapped in @require_role(...) (auth/decorators.py), which checks the role that auth/middleware.py resolved and verified — independently of what the agent claims.

This is defense in depth: two independent components would both have to be wrong for a cross-role access to succeed.

The agent's own identity claim is verified, not trusted

When the agent calls its own REST API (see agent/api_client.py), it sends X-Acting-Staff-Id and X-Acting-Role headers alongside a shared service secret. auth/middleware.py does not take the role header at face value — it looks up the staff row by ID and confirms the role column actually matches:

staff = Staff.query.get(int(claimed_staff_id))
if staff and staff.active and staff.role == claimed_role:
    g.staff_id = staff.staff_id
    g.role = staff.role   # taken from the DB record, not the header

A prompt-injected or misprompted agent claiming to be a different role than the real staff member's DB record gets rejected here.
