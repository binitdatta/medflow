Enterprise Architecture

Hospital Chain Agentic AI Chatbot Platform

A secure, role-aware healthcare assistant built with Python 3.12, Flask, Jinja, Bootstrap 5, REST APIs, LangChain, LangGraph, SQLAlchemy, MySQL 8.x, and Keycloak 26.

This architecture supports nurses, physicians, management staff, legal teams, and service operators through specialized AI workflows, governed access, enterprise data services, and auditable integrations.

Platform Purpose

Deliver secure, context-aware assistance to hospital personnel while preserving role boundaries, data protection, traceability, and operational control.

Architecture at a Glance

Role-Based Users

Different hospital roles receive different tools, workflows, and data access.

Identity and Security

Keycloak 26 provides authentication, tokens, role claims, and client separation.

Agentic Orchestration

LangGraph routes requests through specialized, stateful, tool-using workflows.

Enterprise Data

SQLAlchemy and MySQL 8.x persist users, sessions, clinical data, documents, and audit records.

The platform is shared across the hospital chain, but the user experience is not identical for every person. Keycloak roles and application authorization rules determine which AI agent, APIs, records, and actions are available.

Nurses

Vital signs, medication workflows, care plans, handovers, and patient-support activities.

Physicians

Clinical history, diagnoses, orders, procedures, and decision-support workflows.

Management Staff

KPIs, utilization, reports, staffing insights, and operational oversight.

Legal Teams

Policies, contracts, compliance evidence, legal research, and case support.

Service Operators

Facilities requests, maintenance tickets, asset records, and vendor coordination.

Keycloak 26 acts as the OpenID Connect identity provider and OAuth 2.0 authorization server. It authenticates users, issues signed tokens, and supplies claims used by Flask and the AI layer.

PKCE Client for the UI

The interactive web application uses Authorization Code Flow with PKCE. The code verifier protects the authorization-code exchange and reduces the risk of code interception.

Confidential Client for Testing

Trusted API test tools and server-side processes use a confidential client with protected credentials. This keeps interactive-user authentication separate from controlled machine or test access.

Authentication establishes who the caller is. Authorization determines what the caller may view, invoke, modify, or approve.

Python 3.12 and Flask provide the server-side application platform. Jinja renders the web experience, Bootstrap 5 supplies the responsive visual framework, and REST APIs expose reusable business capabilities.

Web Layer

Chat, history, reports, documents, profile, and administrative pages.

API Layer

JSON endpoints for chat, sessions, users, knowledge, documents, workflows, and administration.

Business Services

Conversation, authorization, notification, document, audit, and domain-specific services.

LangGraph controls the workflow: it carries state, chooses the next node, routes requests to authorized subgraphs, handles retries, and supports human approval. LangChain provides prompts, model wrappers, tools, retrievers, memory components, and structured-output utilities used inside those workflows.

Conversation context, user identity, intermediate results, and workflow status.

Conditional Routing

Selects the correct agent, tool, retry path, or rejection path.

Calls approved APIs, SQL queries, search services, and enterprise functions.

Human Oversight

Pauses sensitive or irreversible actions for authorized review.

SQLAlchemy provides ORM models, repositories, transaction management, and connection handling. MySQL 8.x stores application and operational records such as users, roles, patients, encounters, sessions, messages, documents, workflow state, and audit events.

The AI model does not receive unrestricted database access. Application services and authorized tools mediate every data operation.

The platform can integrate with EHR or EMR systems, laboratory services, imaging systems, pharmacy, billing, insurance, notifications, document stores, and other hospital services.

Synchronous Integration

REST APIs support immediate request-response operations such as patient lookup or eligibility checks.

Asynchronous Integration

RabbitMQ, workers, and scheduled jobs support long-running, resilient, and decoupled processing.

Enterprise operation requires more than a functional chatbot. The platform also needs structured logging, metrics, distributed tracing, dashboards, alerting, container deployment, environment separation, encryption, role-based access control, and auditability.

Observability

Logs, metrics, traces, dashboards, and operational alerts.

Deployment

Containers, reverse proxy, CI/CD, and controlled development, test, and production environments.

Security

TLS, token validation, RBAC, encrypted data, and protected secrets.

Auditability

Traceable user actions, model decisions, tool calls, approvals, and data changes.

End-to-End Request Flow

  1. A hospital user signs in through Keycloak 26.
  2. The Flask application receives and validates identity and role information.
  3. The user submits a request through the Jinja and Bootstrap chat interface.
  4. The REST API validates the request and creates or resumes the conversation state.
  5. LangGraph routes the request to the authorized role-specific subgraph.
  6. LangChain tools call approved databases, APIs, search services, or background workers.
  7. Business rules and authorization checks validate the result.
  8. The response is returned to the user and relevant activity is recorded for audit and observability.
