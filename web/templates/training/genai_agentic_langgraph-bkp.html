Generative AI, AI Agents, Agentic AI, LangChain & LangGraph

The five terms that get used almost interchangeably in vendor decks — and aren't the same thing. This page draws the lines between them, then uses LangGraph's role-based routing (the exact pattern MedFlow itself runs on) as the running real-world example.

Generative AI

A model that produces new content — text, code, images, audio — by predicting what comes next, trained on large amounts of existing content.

Example: Claude writing a discharge summary paragraph, or an image model generating a picture from a text prompt. One prompt in, one output out — no memory of what happened before, no ability to go do something in the world.

AI Agent

A generative model given tools it can choose to call — a weather API, a database query, a search function — plus enough structure to decide which tool fits the request and act on the result.

Example: A single MedFlow tool call — the Pharmacist assistant calling check_drug_interactions("warfarin", "aspirin") instead of guessing the interaction from memory. One decision, one tool, one result.

Agentic AI

Multiple tool calls chained across multiple steps, with the model deciding the order, checking its own results, and looping back to try again — not a fixed script, a genuine multi-step decision process.

Example: Physician subgraph's "check the chart, then order a CT only if one hasn't already been ordered" prompt from Phase 2 testing — that's the model reading a result and deciding its next action, not just executing a checklist.

LangChain

A library of building blocks for LLM apps: prompt templates, standardized tool definitions (the @tool decorator you've seen in every agent/subgraphs/*.py file), and wrappers around model providers like Anthropic.

Example: Every function in agent/subgraphs/nurse.py — LangChain turns a plain Python function into something Claude can see and decide to call, just by adding one decorator.

LangGraph

Sits on top of LangChain and adds the missing piece: explicit control flow — a graph of named steps ("nodes") and rules for which node runs next ("edges"), so an agent's behavior is a diagram you can draw, not just a prompt you hope behaves consistently.

Example: the whole rest of this page.

LangGraph — Real-Life Examples

Same underlying pattern (a small loop of "decide → act → check → repeat," with an explicit boundary around who can trigger which branch) shows up everywhere once you know to look for it. Click through each one.

You're looking at a live one. Every chat message you send becomes a LangGraph run with exactly two nodes:

agent  --tool call requested-->  tools
  ^                                    |
  |____________________________________|
  |
  no tool call requested
  |
  v
 END

Why a graph instead of one big prompt: the role (Nurse, Pharmacist, Physician, ...) is decided before the graph even starts — by agent/graph.py's ROLE_CONFIG lookup, driven by your Keycloak login, never by anything you type in chat. The graph then loops between the LLM deciding what to do and a tool actually doing it, as many times as needed, until the LLM has a final answer with no more tool calls left to make.

See Architecture Walkthrough for the full request path.

A support inbox gets tickets about billing, technical bugs, and account access. A LangGraph router node reads the incoming ticket, classifies it, and sends it down one of three branches — a Billing subgraph with refund/invoice tools, a Technical subgraph with log-lookup tools, an Account subgraph with password-reset tools.

Same shape as MedFlow's role_router — the only real difference is MedFlow's "classification" is a login (Keycloak role), not a text-classification step, which is a deliberately safer design: the router can't be talked into misrouting by clever ticket text, the way a text-classified support router theoretically could be.

"Book me a trip to Chicago next weekend" needs a flight search tool, a hotel search tool, and a car rental tool — and the results of each affect the others (no point booking a hotel far from where the cheapest flight lands). A LangGraph loop keeps calling tools and re-evaluating until it has a coherent itinerary, then stops and presents it rather than booking anything automatically.

Same shape as the Physician subgraph's chart-then-CT-order prompt: call a tool, look at what came back, decide whether the next tool call is actually still needed, instead of blindly running every tool every time.

A content moderation system drafts a takedown notice, then a node in the graph deliberately stops and waits for a human reviewer to approve before the "actually delete this" tool is allowed to run. The graph has a real pause built into its structure, not just a prompt asking the model to "please confirm first" and hoping it remembers to.

Same shape as the Nurse subgraph's medication-administration confirmation you tested in Phase 1 — the assistant asks "shall I proceed?" before record_medication_administration runs, and (after the multi-turn memory fix) actually carries that pending confirmation into the next message correctly.

"Summarize the last month of news on X" can't be answered with one search call. A LangGraph loop searches, reads results, decides whether it has enough to answer confidently, and if not, searches again with a refined query — possibly several times — before finally writing the summary.

Same shape as the Legal subgraph's audit-trail tools: browse_audit_trail might come back with nothing useful for a vague question, and a well-built graph tries get_audit_trail_for_staff or narrows the date range next, rather than giving up after one empty result.

The one-sentence version of each
Generative AIPredicts and produces content.
AI AgentGenerative AI that can call one tool to act on a decision.
Agentic AIAn agent that chains multiple decisions and tool calls, checking its own work along the way.
LangChainThe toolkit for defining prompts, tools, and model calls.
LangGraphThe toolkit for defining which order those tools and decisions run in, as an explicit, inspectable graph.
