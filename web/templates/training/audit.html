Audit Logging Pattern

Who accessed what, and why — captured at the moment it happens.

Design choice: audit writes live inside each endpoint, not in a separate step

An earlier design considered a dedicated LangGraph "audit_writer" node that runs after the agent's tool loop finishes. Phase 1 instead writes the audit_log row synchronously inside each Flask endpoint (see api/_audit_helper.py's write_audit(), called from every PHI-touching route).

Why: the write happens in the same request/transaction path as the data access itself, whether the caller is a human via the browser, the agent via the internal service channel, or a script via the confidential client's Bearer token. There's no window where a data access could succeed but the audit write gets skipped because the agent's graph run failed partway through afterward.
